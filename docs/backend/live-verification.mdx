## High-signal live policy facts

- `packer_sessions` no longer matches the repository migration. The live manage
  policy checks `orders.production_status IN ('pending','in_progress')`, not the
  non-existent `orders.status`.
- A separate `packer_sessions` policy named `Temporary all authenticated access`
  allows any authenticated user through `auth.uid() IS NOT NULL`. That should be
  reviewed before relying on the stricter policy.
- `get_user_email_by_username(lookup_username text)` is `SECURITY DEFINER` and is
  executable by `anon` and `authenticated`, matching the username-login flow.
- 48 public functions are `SECURITY DEFINER`; many are also executable by `anon`.
  This is much broader than the source-only docs previously established.
- `roles` has a read policy using deprecated `auth.role()`. Future RLS edits
  should use policy `TO` clauses instead.

## Report date logic

The live `fetch_report_instances` overload with `p_tag_ids` uses:

```text
COALESCE(order_pkg_instance.packed_at, MAX(pkd_item.created_at))
```

for completion-style date modes. It accepts `packing_started_at`,
`packing_completed_at`, `item_packed_at`, and falls back to instance creation for
unrecognised modes. `item_packed_at` is treated as a legacy alias for completion.

## Temporary privileges

`temporary_privileges` exists, has RLS, and currently has zero rows. The live
`user_effective_permissions` view and `user_has_permission` function both confirm
that role permission flags are enforced at least inside database authorization
helpers, even though application code does not read the flags directly.
