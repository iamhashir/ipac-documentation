## High-signal live policy facts {#high-signal-live-policy-facts}

- `packer_sessions` no longer matches ال المستودع migration. ال live manage
  policy checks `orders.production_status IN ('pending','in_progress')`, لا ال
  non-existent `orders.status`.
- A separate `packer_sessions` policy named `Temporary all authenticated access`
  allows any authenticated مستخدم through `auth.uid() IS NOT NULL`. That ينبغي be
  reviewed قبل relying on ال stricter policy.
- `get_user_email_by_username(lookup_username text)` هو `SECURITY DEFINER` و هو
  executable بواسطة `anon` و `authenticated`, matching ال username-login flow.
- 48 public functions هي `SECURITY DEFINER`; many هي also executable بواسطة `anon`.
  This هو much broader than ال source-only docs previously established.
- `roles` has a قراءة policy using deprecated `auth.role()`. Future RLS edits
  ينبغي use policy `TO` clauses instead.

## تقرير date logic {#report-date-logic}

ال live `fetch_report_instances` overload مع `p_tag_ids` يستخدم:

```text
COALESCE(order_pkg_instance.packed_at, MAX(pkd_item.created_at))
```

لـ completion-style date modes. It accepts `packing_started_at`,
`packing_completed_at`, `item_packed_at`, و falls back إلى instance creation لـ
unrecognised modes. `item_packed_at` هو treated as a legacy alias لـ completion.
