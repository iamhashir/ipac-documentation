## Context {#context}

IPAC's dépôts have been renamed et moved at least once, et le old names
remain visible dans git history, dans prose inside le applications, et dans build
identifiers. Avant this a été established, source references dans this documentation
could ne be trusted vers resolve.

## Problem {#problem}

Three différent owners appeared dans le available preuve, et old GitHub URLs
**redirect** rather than 404 — so a stale remote keeps working et gives non signal
that it est stale. Without a decision, every source link on this site a été a guess.

## Decision {#decision}

**le canonical organisation est `ipacapps`.** Confirmed 2026-08-19.

le canonical dépôts:

```text
ipacapps/
├── ipac-documentation
├── website          (formerly it-ipac/admin-panel)
└── Mobile
```

Applied dans this dépôt: `organizationName` et all three dépôt URLs dans
`docusaurus.config.ts` now use `ipacapps`, et `SourceRef` resolves both application
dépôts vers live links.

## Alternatives {#alternatives}

**Ne recorded.**

Non artifact evaluates keeping le dépôts under `it-ipac`, ou consolidating them
differently. le rename depuis `admin-panel` vers `website` et le organisation change
sont visible only as outcomes.

## Consequences {#consequences}

### Positive {#positive}

- **Source references resolve.** Every `SourceRef` on this site links vers real code.
  Avant this decision, `Mobile` chemins rendered as plain text parce que inventing a URL
  a été ne acceptable.
- **One place vers change.** Dépôt URLs live dans `customFields.repositories` dans
  `docusaurus.config.ts`. Si le organisation changes again, one edit updates every
  link on le site.
- **`Mobile` est dans an organisation, ne a personal account.** An earlier checkout de
  le même application had `origin` et `upstream` pointing at two *personal*
  accounts. That a été le single largest bus-factor risque identified dans le audit, et
  le actuel remote resolves it.
- **Two ouverte questions closed** — OQ-001 et OQ-010.

### Negative {#negative}

- **Old names persist dans three places**, et they va keep confusing readers:

  | Location | Still says |
  | --- | --- |
  | `website/docs/ARCHITECTURE.md`, `DEVELOPMENT.md`, `ROLES.md` | `admin-panel/` et `ipac_mobile/` |
  | `Mobile/README.md` | a personal-account clone URL et `cd ipac-operations-app` |
  | `website/package.json` | `"name": "ipac-admin-panel"` |
  | `Mobile/app.json` | `slug` et `scheme` de `ipac-operations-app`; Android package `com.ipacoperationsapp.app` |

- **`ipac_mobile` never existed as a directory.** It appears dans `website`'s own
  documents, including a workspace-layout diagram, et would fail a new developer's
  first `cd`.
- **le reason est lost.** Nobody reading this va know whether le move a été
  organisational, administrative, ou incidental.

### Risques {#risks}

- **Silent link rot.** Parce que GitHub redirects old URLs, a wrong organisation name
  produces links that *work* — so le error est invisible until le redirect stops.
  This est why le organisation est stated as a decision here rather than inferred.
- **`ipac-documentation` est unverified.** It est configured as
  `ipacapps/ipac-documentation` pour consistency, but le dépôt does ne exist
  yet, so non remote confirms it.

:::danger Load-bearing identifiers doit ne be renamed automatically

`Mobile/app.json` still declares names derived depuis `ipac-operations-app`. **Do ne
"finish" le rename par changing them.** They sont ne cosmetic:

| Identifier | Value | Why renaming est a product decision |
| --- | --- | --- |
| `android.package` | `com.ipacoperationsapp.app` | This **est** le installed application identity. Change it et you ship a *différent app*: existant installs va ne upgrade, et any store listing identity est lost. |
| `scheme` | `ipac-operations-app` | Backs deep links. Changing it breaks every link already issued. |
| `slug` | `ipac-operations-app` | Ties le project vers its EAS identity, et EAS owns version numbering (`appVersionSource: "remote"`). |

le distinction that matters: **prose names sont simply wrong et devrait be corrected;
build identifiers sont correct as they stand et carry migration consequences.** This
documentation corrected le prose on its own pages et did ne touch either
application. Tracked as [OQ-003](/docs/reference/open-questions#oq-003).

:::

## Actuel State {#current-state}

**dans effect.** Both application checkouts have exactly one remote each, under
`ipacapps`. Non `it-ipac` remote est configured dans either.

Remaining work est dans le application dépôts, ne here: correcting le stale
prose names, et separately deciding whether le `app.json` identifiers devrait ever
change.
