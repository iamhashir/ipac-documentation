## High-signal live policy facts {#high-signal-live-policy-facts}

- `packer_sessions` non longer matches le dépôt migration. le live manage
  policy checks `orders.production_status IN ('pending','in_progress')`, ne le
  non-existent `orders.status`.
- A separate `packer_sessions` policy named `Temporary all authenticated access`
  allows any authenticated utilisateur through `auth.uid() IS NOT NULL`. That devrait be
  reviewed avant relying on le stricter policy.
- `get_user_email_by_username(lookup_username text)` est `SECURITY DEFINER` et est
  executable par `anon` et `authenticated`, matching le username-login flow.
- 48 public fonctions sont `SECURITY DEFINER`; many sont also executable par `anon`.
  This est much broader than le source-only docs previously established.
- `roles` has a lu policy using deprecated `auth.role()`. Future RLS edits
  devrait use policy `TO` clauses instead.

## Rapport date logic {#report-date-logic}

le live `fetch_report_instances` overload avec `p_tag_ids` utilise:

```text
COALESCE(order_pkg_instance.packed_at, MAX(pkd_item.created_at))
```

pour completion-style date modes. It accepts `packing_started_at`,
`packing_completed_at`, `item_packed_at`, et falls back vers instance creation pour
unrecognised modes. `item_packed_at` est treated as a legacy alias pour completion.
